# アラート

アラートは銘柄ごとに保存されます。どのアラートも 2 つのものを比べます：監視する値（`source`：価格、またはあるインジケーターのあるライン）と比較対象（`value`：数値、ある描画のあるライン、またはあるインジケーターのあるライン）です。条件（`trigger`）はチャートライブラリのアラートと同じで、`cross`（交差）、`cross-up`（上抜け）、`cross-down`（下抜け）、`above`（より大きい）、`below`（より小さい）、そしてチャネルの条件 `enter-channel`（チャネルに入る）、`exit-channel`（チャネルから出る）、`inside-channel`（チャネルの内側）、`outside-channel`（チャネルの外側）があります。チャネルの条件は 2 本の境界のあいだのチャネルと比べ、`value` は 2 本の境界 `[a, b]` として書きます（順序は問わず、各足で低いほうを下限、高いほうを上限とします）。入るとは下限を上へ抜けるか上限を下へ抜けること、出るはその逆で、内側・外側は判定するその時点で 2 本の境界のあいだにあるかどうかです。よくある書き方：

- 価格が 68000 を上抜け：`{ trigger: 'cross-up', value: 68000 }`
- 価格がトレンドラインや長方形の下辺と交差：`{ trigger: 'cross', value: { kind: 'drawing', id, level: 'bottom' } }`（`level` は描画のラインで、書かなければ最初のライン。ラインは描かれたとおりに判定します。延長していれば延長部分も判定し、フィボナッチの非表示のレベルは監視できません）
- 価格が長方形から出る（上辺か下辺から出る）：`{ trigger: 'exit-channel', value: [{ kind: 'drawing', id, level: 'top' }, { kind: 'drawing', id, level: 'bottom' }] }`。長方形では「長方形から出る」と呼びます（長方形の 4 つのチャネル条件は、長方形に入る、長方形から出る、長方形の内側、長方形の外側です）。平行チャネルは `base` と `parallel`、フィボナッチは `'0.382'` と `'0.618'` のような 2 つのレベル、価格範囲にも `top` と `bottom` があります
- 価格が 100,000 から 105,000 の価格チャネルに入る：`{ trigger: 'enter-channel', value: [105000, 100000] }`。RSI が 30 から 70 のあいだ：`{ source: { kind: 'indicator', type: 'RSI', key: 'rsi' }, trigger: 'inside-channel', value: [70, 30] }`。境界にはインジケーターのラインも使えます。たとえばボリンジャーバンドの上限バンドと下限バンド
- 価格がヘッド・アンド・ショルダーのネックラインを割り込む、アンカーVWAP や回帰トレンドの上側と交差する：`level` はそれぞれ `'neckline'`、`'vwap'`、`'2'` です（ある比率や標準偏差の位置のラインは、名前がチャートのラベルに書かれた数そのものです。回帰トレンドのラインは `'2'`、`'-2'` と基準線 `'0'` で、外側の 2 本が先なので、「チャネルに入る／出る」はデフォルトで回帰チャネル全体になります。アンカーVWAP のバンドは `'1'`、`'-1'`、フィボナッチ・ファンの時間レベルのレイは `'time-0.382'` のような名前です）
- RSI が 70 より大きい：`{ source: { kind: 'indicator', type: 'RSI', key: 'rsi' }, trigger: 'above', value: 70 }`
- MACD のゴールデンクロス：`{ source: { kind: 'indicator', type: 'MACD', key: 'macd' }, trigger: 'cross-up', value: { kind: 'indicator', type: 'MACD', key: 'signalLine' } }`
- 価格が 20 日移動平均を上抜け：`{ trigger: 'cross-up', value: { kind: 'indicator', type: 'MA', params: { periods: [20] }, key: 'ma20' } }`

インジケーターは、アラート自身が記録したタイプ、パラメーター（`params`）、価格（`source`）で計算し、チャートにそのインジケーターがあるかどうか、パラメーターがあとで変わったかどうかとは関係ありません。そのほかの設定：`timeframe`（どの時間足の足で判定するか。書かなければ現在のチャートの時間足）、`frequency`（`once` は 1 回だけで、発動すると自動で一時停止。`once-per-bar` は足ごとに最大 1 回。`every-time` は条件を満たすたびに）、`onClose`（`true` は確定した足だけで判定し、各足の確定時に最大 1 回。`once` は同じく発動後に一時停止。デフォルトは `false` で、確定前の足でも判定）、`expires`（期限。ミリ秒のタイムスタンプで、`null` は無期限）、`message`（ユーザーが書いたメッセージ。発動時にアラートの文言の後ろに付く）、`sound`（発動時に音を鳴らす。デフォルトでオン）、`enabled`（有効。デフォルトで有効）。すべてのアラートの鳴り方は状態の `alertSound` にあります：`on` をオフにするとどれも鳴らず、`volume` は 0 から 1 の音量です（デフォルトはオンで 1）。メソッドは `setAlertSound({ on?, volume? })` です。チャートにはこの 2 つの画面がないので、ページ側の設定に置いてください。

```ts
const id = await chart.addAlert(
  {
    trigger: 'cross-up',
    value: 70000,
    frequency: 'once-per-bar',
    message: '前回高値を突破'
  },
  'BTCUSDT'
);
await chart.updateAlert(id, { expires: Date.now() + 7 * 86_400_000 });
const watched = (await chart.getAlerts()).filter((alert) => alert.status === 'watching');
```

**ページを開いているあいだ、すべての銘柄を監視します。** アラート（有効で期限切れでないもの）のある銘柄と時間足ごとに、バックグラウンドで見えないチャートが 1 つ動き、アラートの時間足で足を読み込み、リアルタイムデータを受け、インジケーターと描画の位置を計算します。その銘柄と時間足を表示するチャートとまったく同じように判定します。相場の購読はその銘柄を表示しているチャートと共有し、アラートのある銘柄だけを購読し、一時停止・削除・期限切れになると購読を解除します。1 つのアラートはバックグラウンドで 1 回だけ判定するので、チャートが同時にその銘柄を表示していても二重には通知しません。チャートはアラートラインを描くだけで（数値 1 つとの比較なら 1 本、数値 2 つのチャネルなら 2 本。インジケーターのアラートは、チャートに同じ計算のそのインジケーターがあるとき、そのインジケーターのサブペインに描きます）、履歴をリプレイしているときはリプレイの足で発動します（`replay: true`）。アラートラインはドラッグでき、チャネルの 2 本はそれぞれ別にドラッグします。ページを閉じると監視は止まります。

**ページを閉じてもアラートを出す：サーバーに任せる。** サーバーはオープンソースのチャートライブラリの `createAlertEngine()`（チャートを描かない判定器で、判定、インジケーター、描画のコードはチャートと同じもの）で、同じ足、インジケーター、描画をもとに判定するので、判定はページとまったく同じになります。ページ側では、`setRemoteAlerts(statuses)` でアラートを任せます。`statuses` は向こうでの各アラートの状態（`{ a1: 'watching', a2: 'failed' }` など）で、ページはもうどのアラートも監視せず、これらの状態を表示し（渡していないものは `loading`：まだ受け渡しの途中）、アラートウィンドウの下部には「このページを閉じても監視」と書かれます。もう一度呼ぶと状態を置き換え、`null` でページに戻します。向こうで発動したら、`reportAlert(id, { time, price })`（その足の時間と終値）で、ページが自分で発動したときと同じくメッセージを出し、音を鳴らし、`alert` イベント（`remote: true`）を発火させます。1 回だけのアラートは向こうで一時停止し、ページはそれを変えません。`describeAlert(id)` はページが発動時に出すタイトルと本文を返すので、サーバーからプッシュ通知を送るときに同じ文言を使えます。

**サーバーに何を渡すか：`alertSpec()`。** サーバーはページを開かないので、アラートの判定方法を知る必要があります。どの時間足の足で、どの時間足に合成し、どの取引カレンダーを使い、どのインジケーターを読み、どの描画を監視するかです。`alertSpec(alert, symbol, drawings, intervals)` は、ページ上のアラート（`ProChartAlert`）、その銘柄（`SymbolInfo`）、その銘柄の描画（オープンソースのチャートライブラリの `DrawingInput`）、データフィードの時間足（`datafeed.intervals`。銘柄が自分の時間足を書いていないときに使う）を、この仕様（`AlertSpec`）に変えます：`symbol`、`interval`（足はこれで取得）、`timeframe`（合成する時間足。`interval` と同じなら `null`）、`calendar`、`indicators`、`drawings`、`alert`（オープンソースのチャートライブラリの `createAlertEngine()` がそのまま受け取るアラート）。同じ銘柄、同じ足の系列のアラートは判定器を共有し、設定が同じインジケーターは同じ id を共有するので、サーバーは重複して計算しません。計算できないときは `null` を返します：その銘柄にこの時間足を合成できる足がないとき、またはアラートがページだけにあるインジケーター（カスタムインジケーター）を読むときです。アラートが参照する描画やラインが `drawings` にないときは、判定器に渡したあとで、そのアラートを監視できない（`failed`）と報告されます。

```ts
import { alertSpec } from '@kumo-charts/pro-chart';

// alert は getAlerts() が返すアラート、'BTCUSDT' はその銘柄、drawings はその銘柄の描画。
const symbol = await datafeed.resolveSymbol('BTCUSDT');
const spec = alertSpec(alert, symbol, drawings, datafeed.intervals);

if (spec) {
  // この仕様は JSON なので、サーバーに渡して保存でき、向こうはこれをもとに足を取得し判定器を作る。
  await fetch('/my-alerts', { method: 'PUT', body: JSON.stringify(spec) });
}
```

`status` はページが監視しているかどうかを表します：`watching`（リアルタイムデータを監視中）、`loading`（データがまだ届いていない）、`paused`（一時停止中、または 1 回だけのアラートが発動済み）、`expired`（期限切れ）、`failed`（監視できない：銘柄や足が取得できない、またはアラートの描画やインジケーターがなくなった。データフィードが失敗したときは少しして再試行します）。変化すると `alertStatusChange` が発火します。

ユーザー側では、右クリックメニューの「この価格にアラートを追加」はクリック 1 回で追加します（交差、1 回）。「アラートを追加…」、価格軸の「アラートを追加…」、Alt+A、描画の右クリックメニューの「アラートを追加…」、インジケーターの凡例のベルは、どれもアラートウィンドウを開き、対応する価格、描画、インジケーターを入れておきます。アラートラインをダブルクリックするか、右クリックで「アラートを編集…」を選ぶと既存のアラートを変えられます。ウィンドウのいちばん上は 1 文の要約（たとえば「価格 上抜け 66,121.50で通知。15分のバーをリアルタイムで判定し、1回だけ通知。」で、設定に合わせて変わります）で、その下は 3 つのグループに分かれます。条件：監視対象（価格、インジケーター、描画）、インジケーターとプロット、または描画とライン（チャネルの条件は「チャネル」の 2 本のラインで、ラインが 2 本だけの描画では選ぶ必要がありません。フィボナッチ・リトレースメントのデフォルトは 0.382 と 0.618 の 2 レベル）、方法（価格、インジケーター、ラインが 2 本以上ある描画には、チャネルに入る、チャネルから出る、チャネルの内側、チャネルの外側があり、長方形では長方形に入る、長方形から出る、長方形の内側、長方形の外側と呼びます）、価格または比較対象（値。下に現在値が書かれます。価格はメインペインのインジケーターのラインと比較でき、インジケーターは自分の別のラインと比較できます。チャネルの条件は「上限」「下限」の 2 行で、それぞれ数値かインジケーターのライン。価格はデフォルトで上下それぞれ 1%、インジケーターはデフォルトでその最も高い基準線と最も低い基準線、たとえば RSI の 80 と 20）、時間足（各時間足が「リアルタイム」と「確定時」に分かれます。つまり `onClose`）。発動：通知回数（1 回、バーごとに 1 回、毎回）、有効期間（無期限、24 時間、7 日間、30 日間、日時を指定…。指定する日時はチャートで選んだタイムゾーンで入力）。通知：サウンド、メモ。いちばん下には「このページを開いている間だけ監視」と書かれています。ウィンドウには一時停止がありません。一時停止と再開は、ページ独自のアラート一覧で `updateAlert(id, { enabled })` を使って行います。`features: { alerts: false }` はこれらの入口を外し、チャートにアラートラインも描かず、ページは監視をやめます（リプレイ中も発動しません）。アラート自体はこれまで通り保存され、メソッドもこれまで通り使え、再びオンにするとすべて戻ります。
