# ライセンス

商用版のルールは**自分のパソコンでの開発だけはライセンス不要**ということです。自分のパソコンの開発サーバーでは自由に使え、本番の Web サイトやアプリに置くときは商用ライセンスキーが必要です。ライセンスは [kumocharts.com](https://kumocharts.com/ja/#pricing) で購入でき、個人と法人の 2 種類があり、支払いが済むとすぐにライセンスキーが届きます。

## 商用ライセンスに含まれるもの

- 商用版のすべてのコンポーネント：プロチャートと、その中のオーダーフロー、情報駆動型の足、数式インジケーター。
- **クレジット表記は不要**：オープンソース版では利用者にページ上で Kumo Charts を使っていることの表記をお願いしていますが、商用ライセンスでは要りません。チャートの左上には自社の名前とロゴを置けます（`brand` オプション）。
- アップデート期間内にリリースされた新しいバージョンにはすべてアップグレードでき、アップデート期間が過ぎても、すでにリリースされたバージョンはずっと使えます。
- 個人と法人の 2 種類でコンポーネントは同じで、違いは使えるドメインとアプリの数です。

## チャートにライセンスキーを渡す

```ts
import { createProChart } from '@kumo-charts/pro-chart';

// Web サイト
createProChart(container, { datafeed, symbol: '600519.SH', licenseKey: 'KCS1.…' });

// デスクトップアプリ・モバイルアプリ：アプリ ID も渡す（逆ドメイン形式）
createProChart(container, {
  datafeed,
  symbol: '600519.SH',
  licenseKey: 'KCS1.…',
  appId: 'com.acme.charts'
});
```

Vue と React のコンポーネントでは `options` に書きます。ライセンスキーはブラウザ内でオフラインで検証し、サーバーには接続しません。ライセンスキーがないとき、またはライセンスキーがそのページをカバーしていないとき、チャートの左下に「Kumo Charts 商用版 · ライセンス未登録、評価専用」と表示します（画面が中国語・英語・韓国語のときはその言語で表示します）。検証している一瞬は表示しません。

## ライセンスが必要なページ

- **自分のパソコンでの開発**：自分のパソコン（`localhost`、`*.localhost`、`127.*.*.*`、`0.0.0.0`、`::1`）の、開発サーバーがよく使うポートのページはライセンス不要で、ウォーターマークも出ません。Vite の 5173、webpack の 8080、Next.js の 3000、Angular の 4200 などと、使用中のときに順に移る次のいくつかのポートです：`1234`、`1313`、`3000`–`3010`、`4000`–`4010`、`4173`–`4180`、`4200`–`4210`、`4321`–`4330`、`5000`–`5010`、`5173`–`5199`、`5500`–`5510`、`6006`–`6010`、`8000`–`8010`、`8080`–`8090`、`8100`–`8110`、`8787`、`8888`–`8890`、`19006`。
- **Web サイト**：ドメイン名のあるページ（ローカルネットワークの `*.local` とテスト用ドメイン `*.test` を含む）はドメインでライセンスし、ライセンスキーのドメインがそのページをカバーしているときに有効です。`acme.com` は `www.acme.com` を含み、`*.acme.com` はすべてのサブドメインです。ページがどのドメインに数えられるかはそのオリジンで決まります。`<iframe srcdoc>`、`about:blank`、`blob:` のページは、それを作った Web サイトとして数えます。Web サイトが `appId` を渡しても、ドメインだけで判定します。
- **ドメイン名のないページ**はアプリ ID でライセンスします。ファイルから開いたページ（`file:`、デスクトップアプリなど）、アプリ独自のスキーム（iOS アプリの `capacitor://localhost` や、CEF のようなデスクトップアプリが登録したスキーム）、サンドボックス化した iframe、`data:` のページ、そして**自分のパソコン上でこれ以外のポートのページ**です。アプリが自分で立てるサーバーで、Android のハイブリッドアプリの `https://localhost`、Windows の Tauri アプリの `http://tauri.localhost`、Electron アプリがパソコン上で開くポートなどです。`appId` を渡し、ライセンスキーのアプリにそれが含まれているときに有効です。`appId` は逆ドメイン形式（英字で始まる 1 つの部分に、`.` で区切った部分がいくつか続き、英字・数字・`-`・`_` からなり、大文字と小文字を区別しない）で、形式が正しくないと `createProChart()` がその場でエラーを投げます。

1 つのライセンスキーにドメインとアプリ ID の両方を持たせられます。

## 本番の Web サイトには HTTPS が必要

署名の検証に使う `crypto.subtle` を、ブラウザは安全なページ（HTTPS と `localhost`）でしか提供しません。http やローカルネットワークの IP で開くと、ライセンスキーが有効でも検証できず、チャートはウォーターマークを表示します。アプリ内のページでも `crypto.subtle` が使える必要があります（WebView や CEF には通常あります）。

## アップデート期間

ライセンスキーには**アップデート期限日**が付いています。これは利用停止日ではありません。この日まで（当日を含む）にリリースされたバージョンは、このライセンスキーでずっと使えます。それ以降にリリースされたバージョンはカバーされず、アップグレードするには更新して新しいライセンスキーを受け取る必要があります。比べるのはコードのリリース日で、訪問者のパソコンの時計は見ません。

## 通らないときはコンソールを見る

ライセンスキーが現在のページをカバーしていないとき、ブラウザのコンソールに、ドメインまたはアプリごと、コンポーネントごとに 1 回ずつ、`Kumo Charts Commercial:` で始まる理由が出ます。ドメインが違う、アプリ ID が渡されていないか一致しない、このバージョンがアップデート期間の後にリリースされた、ライセンスキーが改変されている、またはページが HTTPS でない、のいずれかです。
