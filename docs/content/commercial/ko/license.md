# 라이선스

상업용의 규칙은 **내 컴퓨터에서 개발할 때만 라이선스가 필요 없다**는 것입니다. 내 컴퓨터의 개발 서버에서는 마음대로 쓰고, 정식 웹사이트나 앱에 올릴 때는 상업 라이선스 키가 있어야 합니다. 라이선스는 [kumocharts.com](https://kumocharts.com/ko/#pricing)에서 구매하며, 개인과 기업 두 종류이고, 결제하면 바로 라이선스 키를 받습니다.

## 상업 라이선스에 포함되는 것

- 상업용의 모든 컴포넌트: 프로 차트와 그 안의 오더 플로우, 정보 기반 바, 수식 지표.
- **출처 표기 불필요**: 오픈 소스 버전은 사용자에게 페이지에 Kumo Charts를 썼다고 표기하도록 요청하지만, 상업 라이선스는 필요 없습니다. 차트 왼쪽 위에는 자신의 이름과 로고를 둡니다(`brand` 옵션).
- 업데이트 기간 안에 출시된 새 버전으로는 모두 업그레이드할 수 있고, 업데이트 기간이 지나도 이미 출시된 버전은 영원히 쓸 수 있습니다.
- 개인과 기업 두 종류의 컴포넌트는 같으며, 차이는 쓸 수 있는 도메인과 앱의 개수입니다.

## 차트에 라이선스 키 주기

```ts
import { createProChart } from '@kumo-charts/pro-chart';

// 웹사이트
createProChart(container, { datafeed, symbol: '600519.SH', licenseKey: 'KCS1.…' });

// 데스크톱·모바일 앱: 앱 ID도 줍니다(역도메인 형식)
createProChart(container, {
  datafeed,
  symbol: '600519.SH',
  licenseKey: 'KCS1.…',
  appId: 'com.acme.charts'
});
```

Vue와 React 컴포넌트에서는 `options`에 씁니다. 라이선스 키는 브라우저 안에서 오프라인으로 검증하며 서버에 접속하지 않습니다. 라이선스 키가 없거나 라이선스 키가 이 페이지를 포함하지 않으면 차트 왼쪽 아래에 "Kumo Charts 상업용 · 라이선스 미등록, 평가 전용"을 표시합니다(화면이 중국어, 영어, 일본어일 때는 그 언어로 표시합니다). 검증하는 그 순간에는 표시하지 않습니다.

## 라이선스가 필요한 페이지

- **내 컴퓨터에서 개발**: 내 컴퓨터(`localhost`, `*.localhost`, `127.*.*.*`, `0.0.0.0`, `::1`)에서 개발 서버가 흔히 쓰는 포트의 페이지는 라이선스가 필요 없고 워터마크도 표시하지 않습니다. Vite의 5173, webpack의 8080, Next.js의 3000, Angular의 4200 같은 포트와, 사용 중일 때 차례로 넘어가는 다음 몇 개입니다: `1234`, `1313`, `3000`–`3010`, `4000`–`4010`, `4173`–`4180`, `4200`–`4210`, `4321`–`4330`, `5000`–`5010`, `5173`–`5199`, `5500`–`5510`, `6006`–`6010`, `8000`–`8010`, `8080`–`8090`, `8100`–`8110`, `8787`, `8888`–`8890`, `19006`.
- **웹사이트**: 도메인이 있는 페이지(로컬 네트워크의 `*.local`과 테스트 도메인 `*.test` 포함)는 도메인으로 라이선스하며, 라이선스 키의 도메인이 그 페이지를 포함해야 합니다. `acme.com`은 `www.acme.com`을 포함하고, `*.acme.com`은 모든 하위 도메인입니다. 페이지가 어떤 도메인으로 계산되는지는 그 출처(origin)로 정합니다. `<iframe srcdoc>`, `about:blank`, `blob:` 페이지는 그것을 만든 웹사이트로 계산합니다. 웹사이트가 `appId`를 줘도 도메인으로만 판단합니다.
- **도메인이 없는 페이지**는 앱 ID로 라이선스합니다. 파일에서 연 페이지(`file:`, 예를 들어 데스크톱 앱), 앱 자체의 스킴(iOS 앱의 `capacitor://localhost`, CEF 같은 데스크톱 앱이 등록한 스킴), 샌드박스 iframe, `data:` 페이지, 그리고 **내 컴퓨터에서 이 밖의 포트에 있는 페이지**입니다. 앱이 직접 띄운 서버로, Android 하이브리드 앱의 `https://localhost`, Windows에서 Tauri 앱의 `http://tauri.localhost`, Electron 앱이 컴퓨터에 여는 포트 등입니다. `appId`를 주고, 라이선스 키의 앱에 그것이 있어야 합니다. `appId`는 역도메인 형식(영문자로 시작하는 한 부분에 `.`으로 구분한 여러 부분이 이어지고, 영문자, 숫자, `-`, `_`로 이루어지며, 대소문자를 구분하지 않음)이며, 형식이 맞지 않으면 `createProChart()`가 바로 오류를 냅니다.

라이선스 키 하나에 도메인과 앱 ID를 함께 담을 수 있습니다.

## 정식 웹사이트는 HTTPS를 써야 합니다

서명 검증에 쓰는 `crypto.subtle`을 브라우저는 안전한 페이지(HTTPS와 `localhost`)에서만 제공합니다. http나 로컬 네트워크 IP로 열면 라이선스 키가 유효해도 검증할 수 없어 차트에 워터마크가 표시됩니다. 앱 안의 페이지도 `crypto.subtle`을 쓸 수 있어야 합니다(WebView, CEF에는 보통 있습니다).

## 업데이트 기간

라이선스 키에는 **업데이트 마감일**이 있으며, 이는 사용 중지일이 아닙니다. 이날까지(이날 포함) 출시된 버전은 이 라이선스 키로 영원히 쓸 수 있고, 그 뒤에 출시된 버전은 포함되지 않으므로 업그레이드하려면 갱신해서 새 라이선스 키를 받아야 합니다. 비교하는 것은 코드의 출시일이며, 방문자 컴퓨터의 시계는 보지 않습니다.

## 통과하지 못하면 콘솔을 보세요

라이선스 키가 현재 페이지를 포함하지 않으면 브라우저 콘솔에 도메인이나 앱마다, 컴포넌트마다 한 번씩 `Kumo Charts Commercial:`로 시작하는 이유가 나옵니다. 도메인이 맞지 않음, 앱 ID를 주지 않았거나 일치하지 않음, 이 버전이 업데이트 기간 이후에 출시됨, 라이선스 키가 변조됨, 또는 페이지가 HTTPS가 아님 중 하나입니다.
