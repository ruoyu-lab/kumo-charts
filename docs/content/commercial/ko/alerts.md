# 알림

알림은 종목별로 저장됩니다. 알림마다 두 가지를 비교합니다: 감시하는 값(`source`: 가격, 또는 어떤 지표의 어떤 선)과 비교 대상(`value`: 숫자 하나, 어떤 그리기의 어떤 선, 또는 어떤 지표의 어떤 선)입니다. 조건(`trigger`)은 차트 라이브러리의 알림과 같아서 `cross`(교차), `cross-up`(상향 교차), `cross-down`(하향 교차), `above`(초과), `below`(미만), 그리고 채널 조건 `enter-channel`(채널 진입), `exit-channel`(채널 이탈), `inside-channel`(채널 내부), `outside-channel`(채널 외부)이 있습니다. 채널 조건은 두 경계 사이의 채널과 비교하며, `value`는 두 경계 `[a, b]`로 씁니다(순서는 상관없고, 봉마다 낮은 쪽을 하단, 높은 쪽을 상단으로 삼습니다). 진입은 하단을 위로 뚫거나 상단을 아래로 뚫는 것이고, 이탈은 그 반대이며, 내부·외부는 판단하는 그때 두 경계 사이에 있는지입니다. 자주 쓰는 형태:

- 가격이 68000을 상향 교차: `{ trigger: 'cross-up', value: 68000 }`
- 가격이 추세선이나 사각형의 아랫변과 교차: `{ trigger: 'cross', value: { kind: 'drawing', id, level: 'bottom' } }`(`level`은 그리기의 선이며, 쓰지 않으면 첫 번째 선. 선은 그려진 모양대로 판단합니다. 연장했다면 연장한 부분도 판단하고, 피보나치의 숨긴 레벨은 감시할 수 없습니다)
- 가격이 사각형을 벗어남(윗변이나 아랫변으로 나감): `{ trigger: 'exit-channel', value: [{ kind: 'drawing', id, level: 'top' }, { kind: 'drawing', id, level: 'bottom' }] }`. 사각형에서는 "사각형 이탈"이라고 부릅니다(사각형의 네 가지 채널 조건은 사각형 진입, 사각형 이탈, 사각형 내부, 사각형 외부). 평행 채널은 `base`와 `parallel`, 피보나치는 `'0.382'`와 `'0.618'` 같은 두 레벨, 가격 범위에도 `top`과 `bottom`이 있습니다
- 가격이 100,000에서 105,000 사이의 가격 채널에 진입: `{ trigger: 'enter-channel', value: [105000, 100000] }`. RSI가 30에서 70 사이: `{ source: { kind: 'indicator', type: 'RSI', key: 'rsi' }, trigger: 'inside-channel', value: [70, 30] }`. 경계는 지표의 선이어도 됩니다. 예를 들어 볼린저 밴드의 상한선과 하한선
- 가격이 헤드 앤 숄더의 넥라인을 깨거나, 앵커드 VWAP이나 회귀 추세의 위쪽 선과 교차: `level`은 각각 `'neckline'`, `'vwap'`, `'2'`입니다(어떤 비율이나 표준편차 위치의 선은 이름이 차트 라벨에 적힌 그 숫자입니다. 회귀 추세의 선은 `'2'`, `'-2'`와 기준선 `'0'`이고 바깥쪽 두 선이 먼저이므로, "채널 진입/이탈"은 기본으로 회귀 채널 전체가 됩니다. 앵커드 VWAP의 밴드는 `'1'`, `'-1'`, 스피드 저항 팬의 시간 레벨 레이는 `'time-0.382'` 같은 이름입니다)
- RSI가 70 초과: `{ source: { kind: 'indicator', type: 'RSI', key: 'rsi' }, trigger: 'above', value: 70 }`
- MACD 골든 크로스: `{ source: { kind: 'indicator', type: 'MACD', key: 'macd' }, trigger: 'cross-up', value: { kind: 'indicator', type: 'MACD', key: 'signalLine' } }`
- 가격이 20일 이동평균을 상향 교차: `{ trigger: 'cross-up', value: { kind: 'indicator', type: 'MA', params: { periods: [20] }, key: 'ma20' } }`

지표는 알림이 스스로 기록해 둔 유형, 파라미터(`params`), 가격(`source`)으로 계산하며, 차트에 그 지표가 있는지, 파라미터가 나중에 바뀌었는지와는 상관없습니다. 그 밖의 설정: `timeframe`(어느 주기의 봉으로 판단할지. 쓰지 않으면 현재 차트의 주기), `frequency`(`once`는 한 번만, 울린 뒤 자동으로 일시정지. `once-per-bar`는 봉마다 최대 한 번. `every-time`은 조건을 만족할 때마다), `onClose`(`true`면 마감된 봉으로만 판단하며 봉이 마감될 때마다 최대 한 번. `once`는 마찬가지로 울린 뒤 일시정지. 기본값 `false`는 봉이 마감되기 전에도 판단), `expires`(만료 시간. 밀리초 타임스탬프이며, `null`은 만료 없음), `message`(사용자가 쓴 메시지. 울릴 때 알림 문구 뒤에 붙음), `sound`(울릴 때 소리를 냄. 기본으로 켜짐), `enabled`(켜짐. 기본값은 켜짐). 모든 알림이 어떻게 울리는지는 상태의 `alertSound`에 있습니다: `on`을 끄면 어떤 알림도 소리를 내지 않고, `volume`은 0에서 1까지의 음량입니다(기본은 켜짐, 1). 메서드는 `setAlertSound({ on?, volume? })`입니다. 차트에는 이 두 가지의 화면이 없으니 페이지 자체의 설정에 두세요.

```ts
const id = await chart.addAlert(
  {
    trigger: 'cross-up',
    value: 70000,
    frequency: 'once-per-bar',
    message: '전고점 돌파'
  },
  'BTCUSDT'
);
await chart.updateAlert(id, { expires: Date.now() + 7 * 86_400_000 });
const watched = (await chart.getAlerts()).filter((alert) => alert.status === 'watching');
```

**페이지가 열려 있는 동안 모든 종목을 감시합니다.** 알림(켜져 있고 만료되지 않은 것)이 있는 종목과 주기마다 백그라운드에 보이지 않는 차트가 하나 있어, 알림의 주기로 봉을 불러오고, 실시간 데이터를 받고, 지표와 그리기의 위치를 계산하며, 그 종목과 주기를 표시하는 차트와 완전히 똑같이 판단합니다. 시세 구독은 그 종목을 표시하는 차트와 함께 쓰고, 알림이 있는 종목만 구독하며, 일시정지·삭제·만료되면 구독을 해지합니다. 알림 하나는 백그라운드에서 한 번만 판단하므로, 차트가 동시에 그 종목을 표시해도 두 번 알리지 않습니다. 차트는 알림선만 그리며(숫자 하나와 비교하면 한 줄, 숫자 두 개의 채널이면 두 줄. 지표의 알림은 차트에 계산이 같은 그 지표가 있을 때 그 지표의 보조 창에 그립니다), 과거를 리플레이할 때는 리플레이한 봉으로 울립니다(`replay: true`). 알림선은 끌 수 있고, 채널의 두 선은 각각 따로 끕니다. 페이지를 닫으면 더 이상 감시하지 않습니다.

**페이지를 닫아도 알림: 서버에 맡기기.** 서버는 오픈 소스 차트 라이브러리의 `createAlertEngine()`(차트를 그리지 않는 판단기로, 판단, 지표, 그리기 코드는 차트와 같은 것)으로 같은 봉, 지표, 그리기를 바탕으로 판단하므로, 판단이 페이지와 완전히 같습니다. 페이지 쪽에서는 `setRemoteAlerts(statuses)`로 알림을 맡깁니다. `statuses`는 그쪽에서의 알림마다의 상태(예: `{ a1: 'watching', a2: 'failed' }`)이며, 페이지는 더 이상 어떤 알림도 감시하지 않고 이 상태들을 표시하며(주지 않은 것은 `loading`: 아직 넘기는 중), 알림 창 아래에는 "이 페이지를 닫아도 감시"라고 적힙니다. 다시 호출하면 상태를 바꾸고, `null`이면 페이지로 되돌립니다. 그쪽에서 울리면 `reportAlert(id, { time, price })`(그 봉의 시간과 종가)로 페이지가 스스로 울린 것과 똑같이 메시지를 띄우고, 소리를 내고, `alert` 이벤트(`remote: true`)를 내보냅니다. 한 번만 울리는 알림은 그쪽에서 일시정지하며, 페이지는 그것을 바꾸지 않습니다. `describeAlert(id)`는 페이지가 울릴 때 쓰는 제목과 본문을 주므로, 서버가 푸시를 보낼 때 같은 말을 쓸 수 있습니다.

**서버에 무엇을 넘기나: `alertSpec()`.** 서버는 페이지를 열지 않으므로 알림을 어떻게 판단하는지 알아야 합니다. 어느 주기의 봉으로, 어떤 주기로 합성하고, 어떤 거래 캘린더를 쓰고, 어떤 지표를 읽고, 어떤 그리기를 감시하는지입니다. `alertSpec(alert, symbol, drawings, intervals)`는 페이지의 알림 하나(`ProChartAlert`), 그 종목(`SymbolInfo`), 그 종목의 그리기(오픈 소스 차트 라이브러리의 `DrawingInput`), 데이터 피드의 주기(`datafeed.intervals`. 종목이 자기 주기를 쓰지 않았을 때 사용)를 이 명세(`AlertSpec`)로 바꿉니다: `symbol`, `interval`(봉은 이것으로 가져옴), `timeframe`(합성하는 주기. `interval`과 같으면 `null`), `calendar`, `indicators`, `drawings`, `alert`(오픈 소스 차트 라이브러리의 `createAlertEngine()`이 그대로 받는 알림). 같은 종목, 같은 봉 계열의 알림은 판단기를 함께 쓰고, 설정이 같은 지표는 id를 함께 쓰므로 서버는 중복 계산하지 않습니다. 계산할 수 없으면 `null`을 돌려줍니다: 그 종목에 이 주기를 합성할 수 있는 봉이 없거나, 알림이 페이지에만 있는 지표(사용자 지표)를 읽을 때입니다. 알림이 가리키는 그리기나 선이 `drawings`에 없으면, 판단기에 넘긴 뒤 그 알림을 감시할 수 없다(`failed`)고 알려 옵니다.

```ts
import { alertSpec } from '@kumo-charts/pro-chart';

// alert는 getAlerts()가 준 알림 하나, 'BTCUSDT'는 그 종목, drawings는 그 종목의 그리기.
const symbol = await datafeed.resolveSymbol('BTCUSDT');
const spec = alertSpec(alert, symbol, drawings, datafeed.intervals);

if (spec) {
  // 이 명세는 JSON이므로 서버에 넘겨 저장할 수 있고, 그쪽은 이것대로 봉을 가져와 판단기를 만듭니다.
  await fetch('/my-alerts', { method: 'PUT', body: JSON.stringify(spec) });
}
```

`status`는 페이지가 감시하고 있는지를 알려 줍니다: `watching`(실시간 데이터를 감시 중), `loading`(데이터가 아직 오는 중), `paused`(일시정지됨, 또는 한 번만 울리는 알림이 이미 울림), `expired`(만료됨), `failed`(감시할 수 없음: 종목이나 봉을 가져올 수 없거나, 알림의 그리기나 지표가 없어짐. 데이터 피드가 실패했을 때는 잠시 뒤 다시 시도). 바뀌면 `alertStatusChange`를 내보냅니다.

사용자 쪽에서는, 우클릭 메뉴의 "이 가격에 알림 추가"는 클릭 한 번으로 추가합니다(교차, 한 번). "알림 추가…", 가격축의 "알림 추가…", Alt+A, 그리기 우클릭 메뉴의 "알림 추가…", 지표 범례의 종 모양 아이콘은 모두 알림 창을 열고 해당하는 가격, 그리기, 지표를 채워 둡니다. 알림선을 더블클릭하거나 우클릭에서 "알림 편집…"을 고르면 기존 알림을 바꿉니다. 창 맨 위에는 한 문장 요약(예: "가격 상향 교차 66,121.50일 때 알림. 15분 봉 기준 실시간으로 판단, 한 번만 알림."이며, 설정에 따라 바뀝니다)이 있고, 그 아래는 세 그룹으로 나뉩니다. 조건: 감시 대상(가격, 지표, 그리기), 지표와 플롯 또는 그리기와 선(채널 조건은 "채널"의 두 선이며, 선이 둘뿐인 그리기는 고를 필요가 없습니다. 피보나치 되돌림의 기본값은 0.382와 0.618 두 레벨), 방식(가격, 지표, 선이 둘 이상인 그리기에는 모두 채널 진입, 채널 이탈, 채널 내부, 채널 외부가 있고, 사각형에서는 사각형 진입, 사각형 이탈, 사각형 내부, 사각형 외부라고 부릅니다), 가격 또는 비교 대상(값. 아래에 현재가가 적힙니다. 가격은 메인 창의 지표 선과 비교할 수 있고, 지표는 자기의 다른 선과 비교할 수 있습니다. 채널 조건은 "상한", "하한" 두 줄로 각각 숫자나 지표의 선이며, 가격은 기본으로 위아래 각각 1%, 지표는 기본으로 가장 높은 기준선과 가장 낮은 기준선, 예를 들어 RSI의 80과 20), 주기(주기마다 "실시간"과 "마감 시"로 나뉨. 즉 `onClose`). 발동: 알림 횟수(한 번, 봉마다 한 번, 매번), 유효 기간(계속 유효, 24시간, 7일, 30일, 시간 지정…. 지정 시간은 차트에서 고른 시간대로 입력). 알림: 소리, 메모. 맨 아래에는 "이 페이지가 열려 있는 동안만 감시"라고 적혀 있습니다. 창에는 일시정지가 없으며, 일시정지와 재개는 페이지 자체의 알림 목록에서 `updateAlert(id, { enabled })`로 합니다. `features: { alerts: false }`는 이 입구들을 없애고, 차트에 알림선도 그리지 않으며, 페이지는 더 이상 감시하지 않습니다(리플레이 중에도 울리지 않음). 알림 자체는 그대로 저장되고 메서드도 그대로 쓸 수 있으며, 다시 켜면 모두 돌아옵니다.
